# pechynho skills

Agent workflow skills for **Claude Code** and **Codex**, built from one shared source. Skills are
invoked with the `pechynho:` prefix: `/pechynho:planning` in Claude Code, `$pechynho:planning` in Codex.

| Skill | What it does |
|---|---|
| `planning` | Exploration and brainstorming, business decided by the user, PRD and JSON tasks, independent plan validation. |
| `programming` | Implementation with tests, delegation by difficulty and risk, integration and verification by the main agent. |
| `code-review` | Review split by perspectives, independent verification of findings, business questions and synthesis. |
| `playwright-testing` | Headless click-through and visual testing in the dev environment by testers with bounded scenario groups. |
| `feature-delivery` | The whole pass from plan through implementation, click-through and review to the first version, with resumable progress. Explicit invocation only. |
| `feature-feedback` | Record of user feedback with stable IDs and status, targeted plan updates and implementation. |
| `handoff` | Handover of work in progress to another agent via a temporary document and a prompt to copy. |

Install the whole plugin; the skills link to each other and are not meant to be installed one by one.

## Install

### Claude Code

```bash
claude plugin marketplace add Pechynho/pechynho-skills
claude plugin install pechynho@pechynho-skills
```

Installs the skills and the subagents `pechynho:worker`, `pechynho:worker-light`,
`pechynho:analyst` (read-only) and `pechynho:browser-tester`. Update with
`claude plugin marketplace update pechynho-skills` after a new version.

### Codex

```bash
codex plugin marketplace add Pechynho/pechynho-skills
codex plugin add pechynho@pechynho-skills
```

Codex plugins cannot ship custom agents yet, so install them from a checkout of this repository:

```bash
scripts/install-codex-agents.py            # writes pechynho_*.toml into ${CODEX_HOME:-~/.codex}/agents
scripts/install-codex-agents.py --uninstall
```

Codex has no model aliases, so the installer resolves the newest listed `*-sol` (stronger tier) and
`*-luna` (weaker tier) model from Codex's local model catalog (`~/.codex/models_cache.json`) and
writes it into the agents. Re-run it when new models come out; nothing in this repository needs to
change. Claude Code agents use the `opus` and `sonnet` aliases, which always point to the latest models.

Update with `codex plugin marketplace upgrade pechynho-skills`.

## Project configuration

The skills are project-agnostic. A project can tune them in its `AGENTS.md` / `CLAUDE.md`:

```markdown
## Agent skills
- plans_dir: docs/plans
- work_dir: var/agent-work            # optional; must be gitignored. Default: ${TMPDIR:-/tmp}/agent-work/<repo>-<hash>
- checks: `make lint`, `make test`
- dev_env: docs/dev-environment.md     # dev URL, test accounts, data preparation, how to verify the dev DB
- handoff_prefix: myproject
```

Every value has a default; see [project context](base/shared/project-context.md). The universal
workflow rules the skills rely on are in [ground rules](base/shared/ground-rules.md); project rules
apply on top of them.

## Repository layout

```text
base/                       shared, tool-neutral source (edit here)
├── skills/<name>/          SKILL.md + references/
├── shared/                 ground rules, project context, delegation, business questions
└── agents/                 subagent roles (body + name/description)
overlays/
├── claude/                 plugin.json, extra SKILL.md frontmatter, agent frontmatter (model, tools)
└── codex/                  plugin.json, agents/openai.yaml per skill, custom agent settings (default model, sandbox)
plugins/                    GENERATED by scripts/build.py, committed so that git installs work
├── claude/                 Claude Code plugin (.claude-plugin/plugin.json, skills/, agents/)
└── codex/                  Codex plugin (.codex-plugin/plugin.json, skills/, custom-agents/)
.claude-plugin/marketplace.json   Claude marketplace -> plugins/claude
.agents/plugins/marketplace.json  Codex marketplace  -> plugins/codex
```

Platform-specific passages inside base Markdown are wrapped in
`<!-- platform:claude -->` … `<!-- /platform -->` (or `codex`); the build keeps only the matching ones.
The build also copies `base/shared/` into every skill, so each installed skill is self-contained, and
fails on broken relative links or anchors.

## Development

```bash
scripts/build.py           # regenerate plugins/
scripts/build.py --check   # verify plugins/ is up to date
claude plugin validate . --strict
```

Bump `VERSION` for every release; Claude Code updates installed plugins only when the version changes.
